# S2.7 — Shift sequences, in-game integration and acceptance evidence

## Current production motion gate

Production now loads the S29 shallow-wok asset through `createShiftSequenceRig`, including all five preserved clips and the separate concealed-gun actuator. The historical sections below describe how the earlier S27 preview was introduced; their candidate-only production statements are not current integration descriptions. This acceptance step changes no live character, asset, scale, joint, animation clip or gameplay behavior.

The production Chromium harness now saves a deterministic PNG sequence and a VP9 WebM for each of idle, walk, talk, turn and weapon playback. The first four sequences sample one complete authored clip cycle in 24 phases. The weapon sequence records 60 phases over three simulated seconds: deploy, fire, then retract. Frames come from the actual installed S29 mesh in the real game scene, using a fixed three-quarter camera envelope derived from its measured neutral bounds. Each frame independently measures the current skinned mesh bounds for projected size and checks that it stays inside the fixed envelope; the envelope is not passed off as the actor's height.

Each sequence records joint quaternions and head-local face vertices. The gate requires the intended joint to move, the face to remain fixed to the head, and the gun to stay hidden in non-weapon modes. The weapon sequence must spin while firing and finish fully hidden with zero spin. Existing actual-game combat, skin/road contact, Qwerty talk and both failed-production-request fallback gates remain in the same run.

`ffmpeg` encodes the saved rendered frames at the simulation's timebase. `ffprobe` then decodes/counts frames and verifies the expected count, 1600×1000 dimensions and matching timebase. These are deterministic playback records, not wall-clock frame-rate measurements. CI explicitly installs the encoder and uploads the videos, frames and `results.json` through the existing evidence artifact.

The live-GLB Node regression separately checks that every clip moves its intended joint and skinned geometry, then releases the hip, knee, head, root and wrist back to their rest rotations when returning to idle. The idle spine sway is intentionally retained. The concealed weapon must fully retract, stop spinning, and leave the white face material unchanged after each mode.

Evidence files: `shift-motion-{idle,walk,talk,turn,weapon}.webm`, their numbered frame directories, and `production-motion-*` records in `results.json`. The production caller remains `world3d.js` → `createShiftSequenceRig` → `update(dt, options)`.

All 89 Node tests, 50 Python tests and the full production Chromium run passed locally. The regenerated report has no browser errors. Representative source and decoded video frames were opened and inspected; the five decoded frame counts and timebases passed. Cold independent GLEE review covers this gate; merged-commit CI is checked separately after publication.

**Acceptance boundary:** this establishes clip playback, joint/skin response, release to idle, fixed graphic attachment, weapon states and graceful loading fallback. It does not establish translating locomotion, planted-foot locking, slope articulation, a performance budget, public deployment, or the owner's final approval of the complete artwork. S2.2, S2.4 and M5 locomotion work remain open.

Only exact `localhost` or `127.0.0.1` hostnames permit any QA query. The explicit missing-asset fallback path intentionally exercises retaining Shift's previously visible procedural character. In S2.7 QA, the controller replaces the previous instant-visible gun with concealed wrist geometry **only after the candidate GLB validates**. Deferred projectile origins are sampled from the deployed muzzle at shot activation rather than from the old forearm attachment before deployment. A new guard prevents the legacy barrel spin loop from also rotating the S2.7 rotor.

The existing fallback stays visible if loading or validation throws; only an accepted candidate causes old child meshes to be hidden. Qwerty's recognition of Shift gun activity and the dialogue bubbles remain connected.

## Tests and browser captures

- `tests/test_shift_sequences_s27.py` verifies the original 631,448-byte S2.6 binary prefix, original nodes/skins/meshes/three clips, new valid quaternion samplers, and generator determinism.
- `tests/shift-sequences-s27.test.mjs` loads S2.7 with the actual bundled Three.js r180 GLTFLoader and checks idle/walk/talk/turn/wrist clip weights, unchanged white eyes, six-barrel deploy/spin/retract, required bones, material preservation, strict QA hostname gating and fallback behavior in code.
- `scripts/shift_s27_browser_qa.mjs` launches headless Chromium with software WebGL against `scripts/serve_shift_qa.py` and captures actual game frames, MP4 recordings, and `results.json` for all seven QA modes. It checks the expected active actor and gun/eye states and fails on browser exceptions.
- `.github/workflows/shift-s27-qa.yml` installs Node, Python, Playwright and Chromium; runs `npm test` and all Shift Python unit tests; then captures the seven actual-browser sessions. `shift-s27-browser-evidence` is uploaded even if a job fails so problems can be diagnosed.

To reproduce locally (from a checkout):

```sh
npm ci
npm test
python3 -m unittest discover -s tests -p 'test_shift_*.py'
npm install --no-save playwright@1.56.1
npx playwright install chromium
node scripts/shift_s27_browser_qa.mjs artifacts/shift-s27
```

## S2.7 close-up evidence gate — 2026-10-26

The [passing GitHub Actions run #40409454287](https://github.com/HereLiesAz/hahapewpew/actions/runs/40409454287) produced **seven complete real Chromium captures, all 66 Node tests passing, Shift Python tests passing, and a zero-error `results.json`**. All original idle/walk/turn/talk modes were hidden-weapon; weapon/fire were revealed and the fire spindle reached 67.2 radians in deterministic simulation; missing-GLB fallback remained visible. This is a real observed workflow result, not a promised test outcome.

After inspecting the uploaded screenshots, **all wide in-game renders show Shift too small for pixel-level source-art comparisons**, so the passing functional run does **not** prove S2.2 dome/profile, S2.3 eye graphics, or S2.4 foot fidelity. Rather than falsely accepting those steps, the S2.7 acceptance harness now emits a second `*-closeup.png` per mode. It toggles the game's actual **pause** and **follow** controls, places the real PerspectiveCamera 2.3 units from the actor center, and asserts **at least 185 rendered pixels** of projected character height, and center within ±0.15 NDC. The existing gameplay-wide images are retained, and both outputs must be from the actual loaded GLB and fallback actor. The QA camera now faces Shift's actual **world +X** front rather than mistaking the previous QA yaw for its front.

The close-up workflow still requires a new green run and human/independent review of the *actual close-up images* against the original crop. Passing projected size alone is only evidence quality, not design fidelity. No production model change is authorized.

## Geometry-derived camera correction — 2026-10-26

[Actions run #40411958170](https://github.com/HereLiesAz/hahapewpew/actions/runs/40411958170) passed all Node and Shift Python tests and 14 real Chromium captures (7 wide plus 7 close-up). The screenshots nevertheless exposed an invalid **evidence metric**: `projectedHeight=410` had been computed from a guessed 1.29-world-unit line extending above Shift's actor root, **not the actual rendered skinned geometry**. In the screenshot Shift remained about half that size. Green tests did **not** make the false pixel measure true.

The corrected harness imports the same Three.js module as the actual game, calculates an accurate world-space bounding box via `new THREE.Box3().setFromObject(actor,true)` (the S2.7 GLB or legacy fallback), takes its measured center and height, and derives camera distance for a **360-pixel target height**. It now asserts a **minimum of 260 actual projected pixels** and records `measuredWorldHeight` and `measuredWorldWidth` in the downloadable results. Close-up screenshots from the corrected workflow must be inspected before declaring visual fidelity. The source artwork remains the sole authority; this change improves evidence quality rather than modifying the model.
